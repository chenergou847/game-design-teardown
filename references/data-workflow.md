# 数据工作流

用于资料准备与交付检查。小任务可直接核对；多版本、混合来源或批量数据任务再保存工作表、结构化台账和运行记录，不强制增加正文篇幅。

## 成稿前的取舍

按主问题确认核心指标、所需口径及可定位的证据，再选数据。缺项处理：

| 情况 | 处理 |
|---|---|
| 数据可取得且口径一致 | 采用，保留原始资料与定位 |
| 有不同类型的可用证据 | 用它支持实际能回答的问题；例如入选名单只能说明入选情况，不能换算为使用率 |
| 可选指标确实不可得 | 从交付结构删去，必要时简述原因，不留未完成的模板字段 |
| 核心证据缺失会改变范围或结论 | 向用户提出一个关键取舍问题；继续不依赖该答案的工作 |
| 数据集合中存在真实缺失 | 明示未采集、无法核实或不适用；统计与图表说明缺失处理 |

不要把“暂无数据”包装成已证明无差异。需要补证据的限制集中记录，只有影响某个计算时才在该处补充。

## 字段追溯与更正

数据表先固定对象、版本/模式、单位和时间窗；分开原始值、派生值与人工归纳。至少让关键结论能追到来源字段、章节或截图时间点。

修正或混用来源的字段另记：**字段与条件｜原值及出处｜采用值及出处｜更正理由｜对结论的影响**。例如日期按公告更正、数值沿用资料库，应分别定位；改变展示单位保留换算，改变采用来源保留理由。未消除的分歧写明，不取任意平均值或编造精确时序。

台账可以是表格或JSON等实际适用形式。重复出现的对象仍保留当期条件；原始数据与归纳文本分别核对。重采或修订后由台账更新图表和正文，避免三处手工维护不同版本。

## 分层验收

| 层级 | 核查内容 | 能支持的结论 |
|---|---|---|
| 数据一致性 | 原始资料到台账的映射、完整范围、单位、公式、取整、加总及图文数值一致 | 本地数据处理与计算链路自洽；不证明来源本身正确 |
| 来源核查 | 主结论参数是否适用于目标版本/状态；原文定位；不同来源的独立性与分歧处理 | 在所核实资料与条件下有依据；同源转述不算独立印证 |
| 呈现检查 | 图表字号/图例/单位、长表阅读、重复段落、来源编号和本地链接 | 交付内容可读、可定位；不证明设计判断有效 |
| 导出检查（按需） | 正文与附表是否遗漏、图片是否加载；有交互时检查筛选/放大及目标屏幕 | 已检查格式的内容与功能符合要求；未执行项如实记录 |

先完成内容与数据检查，再交给对应格式技能，采用该格式的实际验证流程。检查数量随任务规模确定，不固定期次数、图表数或样本数，也不把单次产物的高评分当作技能普遍可靠的证明。
